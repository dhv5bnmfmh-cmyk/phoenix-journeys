# Phoenix Story Guidelines

> 状态：规范性文件  
> 适用范围：普通 Journey、特别 Journey、故事、发现、词语、来源与多语言支持  
> 最后整理：2026-07-31

Phoenix 的故事不是景点百科，也不是套着风景图的练习题。每段 Journey 都要让 Explorer 进入一个真实地点或可信想象世界，在移动、观察和选择中学习中文。

## 1. 内容目标

每个 Journey 必须同时满足：

1. **可读**：符合当前 Phoenix Lv.1–10 的语言负荷。
2. **可学**：词语、发现和挑战都从故事自然生长。
3. **可信**：事实有来源；传说、争议和原创想象明确标注。
4. **可记**：故事有开场、推进、变化和收束，不是资料堆叠。
5. **可扩展**：同一基础内容能够生成不同等级的完整版本。
6. **可本地化**：中文为主，拼音、越南语和英语完整对齐。

## 2. Journey 类型

### 2.1 普通 Journey

普通 Journey 以真实城市、遗产、建筑、自然景观或文化空间为核心。

必须：

- 使用稳定的 `city-destination` Journey ID。
- 绑定独立城市、目的地、地理节点和存储命名空间。
- 让故事动作发生在该目的地，不能替换地点名后仍然成立。
- 核心事实至少由两条权威来源支持。
- 不把营销文案、旅行攻略或夸张传说当作事实。

### 2.2 特别 Journey

特别 Journey 面向文学、神话、民间传说、奇闻、幻想和夜谈等主题。

必须：

- 由 Phoenix 原创叙事承载，不复制古籍、小说、影视或网络故事。
- 明确说明“灵感来源”与“Phoenix 原创情节”的边界。
- 对神话、传说、宗教和地方口述传统使用尊重、非断言式表达。
- 使用独立视觉、解锁规则和特别入口，但学习流程与品质标准不降低。
- 不伪造历史人物原话或把幻想情节写成真实事件。

## 3. 新 Journey 基础内容包

新增普通 Journey 默认必须提供以下基础包。特别 Journey 除来源类型不同外，遵循相同完整度。

### 3.1 元数据

- 唯一 `id`
- `city`
- `cityCode`
- `place`
- `appBarTitle`
- `storyTitle`
- `headline`
- `description`
- `discoveryTeaser`
- `distanceLabel`
- `stampSymbol`
- 独立 `geoNodeId`

元数据不得复制其他 Journey 后只替换名称。标题、描述、图标和距离文字必须与目的地一致。

### 3.2 基础故事

新 Journey 必须有：

- 4 个经过审查的基础故事 section
- 每个 section 都有稳定 ID
- 每个 section 至少绑定一个有效 source ID
- 4 组顺序完全对应的阅读注释
- 开场、发展、转折、收束四种叙事功能

这 4 个 section 是内容母版，不等于运行时一定显示 4 段。Phoenix 等级适配会根据 Lv.1–10 组织为 1 或 2 个可读段落，但必须保留原始开场与收束含义。

### 3.3 基础词语

新普通 Journey 至少提供 9 个不重复重点词。每个词必须包含：

- 中文词语
- 拼音
- 词性
- 简明中文解释
- Explorer 母语解释，当前为越南语
- 英语解释
- 可识别但不过度装饰的 symbol
- 至少一个自然例句

例句必须：

- 真实包含该词，不得用占位句。
- 与 Journey 或真实使用场景相关。
- 提供中文、拼音、越南语和英语。
- 不等待运行时模型生成。

词语应实际出现在故事或发现中。不得为了凑数加入与内容无关的生词。

### 3.4 基础发现

新 Journey 应提供 4 条基础发现候选。每条包含：

- 中文事实或文化解释
- 拼音
- 简明中文
- 越南语
- 英语

运行时根据等级选取 1–2 条。每条发现必须提供故事之外的新价值，例如：

- 历史背景
- 建筑或空间设计
- 技术原理
- 文化意义
- 词语来源
- 真实性或创作边界说明

不得把故事原句改写后当作发现。

### 3.5 学习提示字段

当前数据模型仍保留 `wonderQuestion` 与 `expressQuestion`，用于兼容和独立 AI 能力。

要求：

- 两个字段必须非空。
- 一个偏理解与观察，一个偏输出与表达。
- 不得询问同一件事。
- 它们不是当前公开六步 Journey 的独立页面。
- 不得因为字段存在而恢复“思考/表达”步骤。

## 4. 叙事结构

### 4.1 开场

开场应快速建立：

- 人物或观察者
- 时间或天气
- 具体地点
- 一个可感知动作、声音、光线或物件

避免用百科定义开头，例如“某地位于……始建于……”。事实可以自然嵌入行动或发现页。

### 4.2 推进

故事中必须发生移动、观察、选择、变化或理解。每一段承担清晰功能，不连续堆叠形容词和历史年份。

### 4.3 转折

转折不需要戏剧化，但应让 Explorer 的理解发生变化，例如：

- 看见结构背后的技术
- 发现不同文化层叠
- 从宏大景观转向普通人的生活
- 意识到传说与史实的边界

### 4.4 收束

结尾应保留一个具体画面、动作、问题或轻微余韵。不得突然结束在统计数字或无关口号。

## 5. 等级适配

Phoenix Lv.1–10 的精确长度见 `CONTENT_QUALITY.md`。

适配时必须：

- 保留原故事第一场景与最后含义。
- Lv.1–2 使用 1 段；Lv.3–10 使用 2 段。
- 第二段不得以未解决的“它、他、因此、于是、后来、最后”等依赖指代开头。
- 降级时简化句法和信息密度，不把内容改成幼稚或失真。
- 升级时增加真实细节、关系和分析，不使用通用填充句。
- 高级等级仍保持可读段落，不变成论文或百科条目。
- 故事、词语、发现、挑战提示和朗读计划同时适配。

## 6. 来源规范

### 6.1 权威来源

普通 Journey 每个目的地至少需要两条独立权威来源。优先顺序：

1. UNESCO
2. 政府或遗产管理机构
3. 博物馆、档案馆或官方景区学术页面
4. 学术出版物或大学资源
5. 一般编辑来源，仅可作辅助

核心事实不能只依赖一般编辑来源。

### 6.2 来源记录

每条来源必须记录：

- 稳定 source ID
- 标题
- 发布者
- URL
- 类型
- 语言
- 关联地理节点
- 验证状态
- 访问日期，适用时
- 必要的边界备注

只有 `verified` 或 `published` 状态的来源可以支持发布内容。

### 6.3 逐段绑定

- 每个故事 section 必须列出 source IDs。
- 不得只在 Journey 顶部放一串来源而无法知道支持哪一段。
- 原创幻想 section 也必须绑定灵感或文化背景来源，并在内容中标注原创边界。
- 来源失效时应替换或记录存档，不可静默保留死链作为唯一证据。

## 7. 事实、传说与原创边界

写作时使用以下标签思维：

- **事实**：有权威来源支持，可以直接陈述。
- **学术解释**：有研究支持，但可能存在不同观点，应使用“通常认为”“研究者指出”等措辞。
- **传说**：必须写明“相传”“民间故事中”“传说认为”。
- **争议**：说明存在不同解释，不替用户下唯一结论。
- **Phoenix 原创**：明确为学习旅程创作，不冒充古籍或史料。

不得编造日期、人物、引语、文物功能或 UNESCO 结论。

## 8. 多语言支持

### 8.1 中文

- 中文是主要学习内容。
- 内容母版使用规范中文，运行时统一简繁转换。
- 不维护会漂移的简体与繁体两套故事。
- 用词自然、现代、可朗读，必要历史术语应解释。

### 8.2 拼音

- 与中文段落和发现逐项对齐。
- 使用带声调拼音。
- 专名、轻声、儿化和多音字应人工复核。
- 标点与句子边界应支持自然朗读和阅读。

### 8.3 越南语与英语

- 越南语是当前默认母语辅助。
- 英语是固定第二辅助语言。
- 翻译应传达含义，不机械逐字对应。
- 专名可保留通行译名并在首次出现时清楚说明。
- 不得在越南语或英语中加入中文原文没有的事实。

## 9. 词语规范

- 词性使用统一中文标签。
- 简明中文解释应比词典定义更适合学习者。
- 越南语与英语解释应短、准、可区分近义词。
- 同一词在全目录只保留一条高质量共享条目时，应确认定义适用于所有 Journey。
- 多义词如在当前 Journey 使用特定义项，应优先显示该义项。
- symbol 不得使用侵权角色、商标或引发文化误读的图形。
- 例句不得只是把地点名硬塞进不自然句子。

## 10. 发现规范

每条 Discovery 应回答“故事之外，我多知道了什么？”

必须：

- 独立成义。
- 至少有 8 个有效中文字符。
- 与其他发现不重复。
- 不与 Story 高度重复。
- 四种语言字段完整。
- 与 Journey 主题和来源一致。

高级等级可以增加比较、因果与文化分析，但不得引入未验证结论。

## 11. 挑战内容规范

挑战固定来自当前 Journey 的故事与发现，模式为：

1. 短文复原
2. 语病修复
3. 补回句子

规则：

- 当前固定 4 个候选答案。
- 每种模式最多 3 次机会。
- 干扰项必须唯一、长度平衡、语法可信、主题相关。
- 不能使用可替换到任何 Journey 的通用错误句。
- 语病修复必须说明错误类型、位置、修改后句子、原因、原则与记忆方法。
- 不同等级使用不同提示深度和训练目标。
- 三次未答对时展示正确答案，不羞辱或惩罚用户。

奖励和复练规则见 `PRODUCT_PRINCIPLES.md` 与 `UI_GUIDELINES.md`。

## 12. 特别 Journey 的视觉叙事

- 每个特别 Journey 规划 10 个与故事进程对应的高清场景。
- 场景之间应有视觉连续性，不像随机图片合集。
- 保留批准的主图，不因补图删除旧图。
- 若已有 10 个有效场景，不重复生成。
- 不使用不自然的闪烁、伪水波、漂浮符号或与故事无关的特效。
- 真实文化人物、宗教意象和神话形象应避免猎奇化与冒犯性重构。

## 13. 禁止内容

不得发布：

- 无来源的历史断言
- 虚构权威机构或链接
- 复制百科、新闻、小说、歌词或旅游文案
- 未授权角色、商标或艺术家仿作
- 与目的地无关的通用故事模板
- 重复发现、重复词语或空白翻译
- 占位例句、占位问题或“待补充”内容
- 把传说写成事实
- 把 Phoenix 原创写成古籍原文
- 为提高难度而堆砌生僻词和超长句

## 14. 内容完成定义

一个新 Journey 只有在以下条件全部满足时才算完成：

- 基础内容包完整
- 来源已验证并逐段绑定
- 地理节点与 Journey ID 唯一
- 四语言支持对齐
- 词语真实出现在故事或发现
- Lv.1–10 均有完整、自然版本
- 三种挑战均为主题专属
- 地图、护照、背景、盖章、分享和存储已接入
- 全目录品质报告批准
- Preview 中完成一次真实移动端体验
