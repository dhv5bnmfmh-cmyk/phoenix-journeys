# Phoenix Content Quality Standard

> 状态：发布 Gate 规范  
> 适用范围：所有普通 Journey、特别 Journey、Phoenix Lv.1–10 与 AI 内容输出  
> 最后整理：2026-07-31

Phoenix 的内容质量不是“看起来不错”即可。每个已发布 Journey 必须经过可重复的全目录检查，并且没有警告、需要修改或阻断项。

## 1. 发布门槛

Journey 内容允许进入 Preview 发布流程的必要条件：

- `blockedCount = 0`
- `needsRevisionCount = 0`
- 每个 Journey × 每个 Phoenix Level 的决定均为 `approved`
- 每个检查组合得分为 100
- 内容、来源、地理绑定、背景、目录和测试一致
- PR 中生成并保留可审查的质量报告

任何 warning 都会使该组合进入 `needsRevision`，因此发布目录必须达到零问题状态。不得降低阈值、跳过等级或删除检查来放行。

## 2. 检查范围

内容品质 Agent 必须遍历：

```text
allJourneyExperiences × Phoenix Lv.1–10
```

当前 PR #140 基线快照：

- 普通 Journey：32
- 特别 Journey：9
- Journey 总数：41
- 等级数：10
- 检查组合：410

这些数字是历史快照，不是运行时配置。新增或删除 Journey 时，目录、报告和 CI 发布证据必须同步更新。

## 3. Phoenix Lv.1–10 故事长度

| Phoenix Level | 中文字符范围 | 运行时段落数 |
|---:|---:|---:|
| Lv.1 | 150–220 | 1 |
| Lv.2 | 200–280 | 1 |
| Lv.3 | 260–340 | 2 |
| Lv.4 | 320–420 | 2 |
| Lv.5 | 380–500 | 2 |
| Lv.6 | 450–580 | 2 |
| Lv.7 | 520–650 | 2 |
| Lv.8 | 580–720 | 2 |
| Lv.9 | 650–800 | 2 |
| Lv.10 | 720–900 | 2 |

规则：

- 字符按中文内容 rune 数计算。
- 低于下限或高于上限均为 critical。
- 段落数必须与等级完全一致。
- 基础母版可以是 4 个 story sections，运行时必须按等级重组为上表的 1–2 段。
- 不得通过重复句、空洞形容词或通用段落机械凑长度。

## 4. 故事结构 Gate

每个等级版本必须：

- 无空段落。
- 保留基础内容的原始开场场景。
- 保留基础内容的最终收束含义。
- 第二段不以未解决的指代或连接词开头。
- 叙事包含清楚的场景、动作与变化。
- 不使用与其他 Journey 可互换的通用填充。
- 特别 Journey 保持其文学、神话或奇谈类型，不被城市旅游 filler 污染。

以下问题为 critical：

- 段落数量不符
- 空段落
- 长度越界
- 丢失开场
- 丢失结尾含义
- 段首依赖未解决的“它、他、因此、后来”等指代

## 5. 多语言对齐 Gate

### 5.1 Story

- 注释数量必须等于运行时故事段落数量。
- 每段必须有拼音、越南语和英语。
- 顺序必须与中文段落一致。
- 字段不得为空或使用占位符。

### 5.2 Discovery

每条必须有：

- 中文 `text`
- 拼音
- 简明中文
- 越南语
- 英语

任何字段缺失均为 critical。

### 5.3 质量要求

自动检查只能确认完整性，人工 Review 还必须确认：

- 拼音声调与专名正确
- 越南语自然、无中文语序硬译
- 英语自然、术语一致
- 翻译没有新增未经来源支持的事实
- 简繁转换后没有混用或错字

## 6. Discovery Gate

运行时每个等级必须显示 1–2 条 Discovery。

必须满足：

- 每条至少 8 个有效中文字符。
- 每条提供独立新信息。
- 同一等级内不重复。
- 与 Story 的中文内容不能高度重复。
- 不同 Journey 不能共享没有地点特征的通用发现。
- 事实和文化解释有对应来源或清楚的原创边界。

重复、空洞、与 Story 高度相似或字段缺失会阻止发布。

## 7. 词语 Gate

每个运行时词表必须：

- 无空词。
- 无重复词。
- 词语实际出现在 Story 或 Discovery。
- 拼音、词性、简明中文、母语与英语定义完整。
- 新增或修改词语提供真实例句。
- 例句确实包含目标词。
- 例句与词义匹配，不使用占位文本。
- 不依赖 Explorer 运行时的模型调用。

基础新普通 Journey 至少提供 9 个词，运行时词数可由等级计划选择，但不能为空或失去核心学习价值。

## 8. 学习提示 Gate

虽然“思考/表达”不在公开六步流程中，数据模型的两个学习提示字段仍必须：

- 非空
- 互不重复
- 一个检查理解，一个引导输出
- 与当前 Journey 主题相关

这些字段用于兼容与独立 AI 能力，不能作为恢复旧页面的理由。

## 9. 挑战质量 Gate

### 9.1 固定契约

- 三种模式：短文复原、语病修复、补回句子。
- 每种模式 4 个候选答案。
- 每种模式最多 3 次机会。
- 第一次正确奖励金币。
- 第二次正确奖励银币。
- 第三次正确奖励铜币。
- 三次未正确奖励碎银，并展示正确答案。
- 重练最弱项不重复奖励。

### 9.2 内容质量

- 四个候选答案必须唯一。
- 长度与视觉高度应平衡。
- 干扰项应具有可信语法或逻辑，不得一眼看出是乱码。
- 所有挑战保持 Journey 主题。
- 语病修复不得回退到与地点无关的通用句。
- 提示随次数递进，不直接泄露答案。
- 讲解包含原因、训练目标、掌握状态和记忆方法。
- 等级变化应改变提示深度、句法负荷和分析要求，但不改变机会与奖励规则。

## 10. 来源与事实 Gate

每个 Journey 必须：

- 至少两条权威来源。
- 核心事实由 UNESCO、政府、博物馆或学术来源支持。
- 每个 Story section 绑定 source ID。
- 来源状态为 `verified` 或 `published`。
- 来源关联正确 geo node。
- 传说、争议和 Phoenix 原创明确标注。
- 不存在虚构 URL、虚构机构或伪造引语。

一般编辑来源可以辅助，但不能单独支撑核心历史事实。

## 11. 地理与系统一致性 Gate

质量检查不仅检查文字。每个 Journey 还必须：

- Journey ID 唯一。
- city ID 与 destination ID 可稳定解析，特殊映射有明确兼容代码和测试。
- geo node 唯一且坐标准确。
- 地图、护照、背景、记录、盖章与存储共享同一 location binding。
- 每日目录、全目录和特别目录无遗漏或重复。
- 免费访问分配与付费全开放使用统一普通 Journey 列表。
- 词库能够从统一 Journey 目录聚合。

## 12. 图片与背景 Gate

每个已发布目的地必须：

- 有项目自有或合法授权的资源。
- 使用高分辨率移动端友好格式。
- 规划 10 个有效离线背景位置。
- 在 Flutter 资产声明中可加载。
- 无破图、低清拉伸、灰柱、水印或外露符号。
- 动效低成本、无闪烁并支持降低动态效果。
- 特别 Journey 的 10 个场景与故事顺序一致。

背景 Agent 只安排真正缺失的位置，不得覆盖已批准资源。

## 13. AI 输出质量 Gate

所有 AI 能力必须：

- 由总编排器路由到专业 Agent。
- 使用经过审查的 Journey context。
- 使用结构化 schema 验证输出。
- 经过隐藏质量 Agent 复核。
- 对格式错误、超时和供应商失败提供安全回退。
- 不在服务端永久保存私人学习正文。
- 不在客户端暴露密钥或内部系统提示。
- 健康检查如实反映当前 provider 与 fallback 状态。

AI 回答不能替代基础 Story、词语、Discovery 和例句的离线内容。

## 14. 评分与状态

当前评分规则：

- 初始分：100
- warning：每项扣 5 分
- critical：每项扣 20 分

发布状态：

- `approved`：无问题
- `needsRevision`：存在 warning 或其他非 critical 问题
- `blocked`：存在 critical 问题

发布 Gate 只接受全部 `approved`。因此最低分和平均分都应为 100。

## 15. 自动化发布证据

Cloudflare PR Preview 工作流必须按顺序：

1. Agent tests
2. Flutter setup 与依赖
3. `flutter analyze`
4. `flutter test`
5. 生成 Journey quality report
6. 上传报告 artifact
7. 更新 PR quality comment
8. 强制执行发布判定
9. 构建 Flutter Web
10. 部署隔离 Worker
11. 验证 Preview 与当前 commit
12. 发布 Preview status 与 PR comment

不得在品质判定前构建并对外发布 Preview。

## 16. 人工 Review

自动报告通过后，Reviewer 仍需抽查：

- 每个新增 Journey 的 Lv.1、Lv.5、Lv.10
- 简体与繁体
- Story 与 Discovery 的语音自然度
- 越南语与英语翻译
- 地图位置与目的地绑定
- 图片裁切和文字对比
- 四个挑战选项的可信度
- 例句是否自然使用目标词
- 回忆、完成、盖章和分享

## 17. 变更管理

当质量规则变化时：

- 更新本文件。
- 更新 auditor / agent / tests。
- 更新质量报告格式或断言。
- 在 `CHANGELOG.md` 记录。
- 不得只改文档或只改测试。

当 Journey 数量变化时：

- 更新统一目录。
- 更新来源、地理、背景与词库注册。
- 更新快照型 CI 证据。
- 确认检查组合 = Journey 总数 × 10。

## 18. 发布阻断示例

以下任一情况必须停止发布：

- Journey 只有页面入口，没有地图、护照或存储接入
- 故事无来源或来源无法验证
- Lv.1–10 任一等级长度越界
- Story / annotation 数量不一致
- Discovery 重复 Story
- 词语或例句为空、重复、未实际使用
- 挑战出现通用 filler、重复答案或奖励可重复领取
- 背景侵权、低清或资源缺失
- AI 密钥、私人记忆或内部提示泄露
- CI 或 Preview 指向的不是当前 PR head
