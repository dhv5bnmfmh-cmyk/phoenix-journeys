# Phoenix AI Development Guide

> 状态：规范性文件  
> 适用范围：Phoenix Journeys 全仓库  
> 维护者：Founder 与项目维护者  
> 最后整理：2026-07-31

本文是 AI 继续开发 Phoenix 时的总入口。它规定开发顺序、决策优先级、分支与发布流程、架构边界、验证要求及文档维护方式。具体产品、UI、故事与品质规则分别由同目录的专项文件负责，本文不重复展开。

## 1. 开发前必须读取

每次开始新任务，AI 必须按以下顺序读取：

1. `docs/PRODUCT_PRINCIPLES.md`
2. `docs/AI_DEVELOPMENT_GUIDE.md`
3. 与任务直接相关的专项规范：
   - UI：`docs/UI_GUIDELINES.md`
   - 故事与旅程内容：`docs/STORY_GUIDELINES.md`
   - 内容与发布质量：`docs/CONTENT_QUALITY.md`
4. `docs/ROADMAP.md`
5. `docs/TODO.md`
6. `docs/REVIEW_CHECKLIST.md`
7. `docs/CHANGELOG.md`
8. 当前 PR、相关源代码、测试与工作流

不得只依赖聊天记忆、旧 PR 描述或单个代码文件继续开发。

## 2. 决策优先级

发生冲突时，按以下优先级处理：

1. Founder 在当前任务中的最新明确决定
2. `PRODUCT_PRINCIPLES.md` 中的长期产品原则
3. 专项规范文件中的明确规则
4. 当前稳定代码与自动化测试形成的可执行契约
5. `ROADMAP.md` 与 `TODO.md` 中的计划
6. `CHANGELOG.md` 中的历史信息

若文档与代码冲突，AI 不得静默选择一方。应先确认哪一方代表最新决定，然后在同一变更中同步代码、测试和文档。历史兼容代码不等于当前产品方向。

## 3. 规范用语

- **必须 / MUST**：不可违反，违反即阻止合并或发布。
- **应该 / SHOULD**：默认遵守；偏离时必须在 PR 中说明原因和替代保护。
- **可以 / MAY**：允许选择，不构成固定要求。
- **已废弃 / DEPRECATED**：只能为迁移或兼容保留，不得扩展或重新暴露给用户。

## 4. 当前产品与技术基线

Phoenix 是以移动端中文学习旅程为核心的 Flutter 产品。当前核心能力包括：

- Phoenix Lv.1–10 自适应学习等级
- 普通旅程与特别旅程统一目录
- 固定公开流程：故事、单词、发现、挑战、回忆、完成
- 简体与繁体全局切换
- 中文主内容，拼音、越南语与英语辅助
- 地图抵达、目的地选择、护照与盖章
- 三连挑战、奖励货币、特别旅程解锁
- 朗读、进度、高亮、续播与语速控制
- 独立跟读训练入口，不嵌入普通旅程步骤
- 客户端学习记录与受约束的 AI 辅助
- PR 隔离 Preview、Flutter CI、内容品质 Agent

当前数量、版本和 PR 快照只记录在 `CHANGELOG.md`。代码不得把文档中的快照当作运行时数据源。

## 5. 开发工作流

### 5.1 读取与定位

开发前必须：

1. 获取当前 PR 的 head branch 与 head commit。
2. 确认任务是在最新批准体验版基础上继续，而不是从旧提交重新开始。
3. 阅读相关实现、模型、服务、测试和工作流。
4. 判断任务是否会影响其他页面、目录、地图、护照、存储、词库、AI、内容品质或 Preview。
5. 先提出最小完整变更范围，再开始修改。

### 5.2 分支规则

- 禁止直接在 `main` 开发。
- 默认继续使用当前有效的开发分支与 Draft PR。
- 新功能与修复应从最新稳定基线创建独立分支。
- 不得覆盖、重写或强推他人的提交，除非 Founder 明确要求。
- 不得把未批准的实验代码混入稳定体验分支。

### 5.3 提交与 Preview

- 完成一个可验证的完整单元后自动提交并推送。
- 不需要反复询问是否推送、更新 PR 或发布 Preview。
- 每个 PR 使用独立 Cloudflare Worker，不能覆盖正式版或其他 PR。
- Preview 必须基于 PR head commit，而不是 merge ref。
- Preview 验证成功后才可发布体验链接。
- 体验链接使用当前 PR 的全开放参数，并携带当前完整 commit 版本。
- 只有准备合并 `main` 时必须再次询问 Founder。

### 5.4 变更范围

- 只修改完成当前目标所需的内容。
- 不得顺手重构无关模块、改名大批文件、改变产品规则或删除兼容层。
- 发现相邻问题时记录到 `TODO.md`，除非它会直接阻断当前功能。
- 所有新增旅程必须同步接入完整系统，禁止只在单个页面“看起来可用”。

## 6. 仓库职责边界

### 6.1 Flutter 应用

`app/` 负责：

- UI 与交互
- Journey 目录、等级适配与本地内容
- 本地状态、学习记录、护照、奖励和解锁
- 朗读、语音选择、进度与高亮
- 客户端调用 AI 服务的安全参数整理

业务规则应集中在可测试的模型、策略、目录和服务中，避免散落在 Widget 条件判断里。

### 6.2 Worker 与 AI

`worker/` 负责：

- 服务端 AI 网关
- Agent 编排、知识上下文和质量审查
- 密钥隔离、输入限制、错误回退和健康检查
- Cloudflare Preview 与发布服务

客户端不得保存、打印或直接调用服务端密钥。

### 6.3 内容与来源

当前 Journey 内容主要由 `app/lib/data/` 与相关模型管理。新增内容必须通过共享目录注册，使用统一 `Journey ID`、地理节点、来源记录和存储命名空间。禁止创建第二套平行目录。

### 6.4 文档

`docs/` 是长期决策与开发规范的唯一入口。规则发生变化时，必须更新最相关的一份文档，并在 `CHANGELOG.md` 记录，不要把同一规则复制到多份文件。

## 7. 核心架构规则

### 7.1 Journey 单一来源

- `allJourneyExperiences` 是普通与特别旅程的统一运行目录。
- 旅程、来源、地理节点、地图、护照、背景、词库和存储必须使用同一个 Journey ID 绑定。
- 目录数量应从运行目录计算；不得在多个位置手工复制数量。
- 若 CI 为发布证据保留固定数量断言，新增或删除旅程时必须同步更新并解释。

### 7.2 Journey ID 与存储

- 普通旅程 ID 使用稳定的 `city-destination` 形式。
- ID 发布后不得随意修改。
- 进度、朗读位置、AI 反馈、盖章与奖励必须按 Journey 命名空间隔离。
- 迁移旧 ID 时必须保留兼容读取并提供测试。

### 7.3 公开学习流程

固定公开流程为：

1. 故事
2. 单词
3. 发现
4. 挑战
5. 回忆
6. 完成与盖章

“思考”和“表达”已从公开流程移除。现有 `wonder`、`express`、Guide 或 Writing 相关字段可能因兼容、AI 能力或旧数据仍存在，但不得直接据此恢复旧页面。任何流程调整都需要 Founder 明确决定、状态迁移和完整回归测试。

### 7.4 等级系统

- Phoenix Lv.1–10 是唯一面向用户的统一等级控制。
- 等级变化必须同时影响故事长度、词汇负荷、发现内容、挑战难度、提示与朗读计划。
- 不得重新加入阻塞式 HSK/TOCFL 弹窗。
- HSK/TOCFL 只作为校准与设置参考，不能形成第二套并行等级状态。

### 7.5 AI Agent 架构

- 所有 AI 模式必须通过唯一总编排器进入，不得由 Flutter 页面直接拼接供应商请求。
- 专业 Agent 必须使用经过审查的 Journey 上下文。
- AI 输出必须经过结构验证和隐藏质量审查；失败时使用明确、可测试的回退。
- 模型供应商和模型版本由服务端网关配置决定，UI 与内容代码不得硬编码。
- 学习者记忆必须限制字段、长度和数量，在客户端整理后再发送。
- 不得将用户私人学习记录持久化到服务端，除非未来有独立、明确的隐私设计与 Founder 批准。
- 服务端请求不得暴露密钥，且应关闭不必要的供应商存储。

### 7.6 朗读与高亮

- 一个 `NarrationController` 是音频、进度、当前字词和高亮的唯一时间源。
- Story 与 Discovery 使用相同朗读契约，但保存独立续播位置。
- 暂停、语速变化、临时词语朗读和返回页面不得让进度倒退或重头播放。
- 恢复已保存位置时不得未经用户操作自动播放。
- iOS Safari 的首次播放必须保留在用户手势调用链中。

详细 UI 行为见 `UI_GUIDELINES.md`。

## 8. 新增旅程的完整接入清单

新增普通或特别旅程时，至少同步以下位置：

- Journey 内容与多语言注释
- 来源记录与内容验证状态
- 统一 Journey 目录
- Phoenix Lv.1–10 自适应内容
- 单词与例句词库
- 发现内容
- 三类挑战及主题专属干扰项
- 地理节点与地图坐标
- `JourneyLocationBinding` 与存储命名空间
- 护照、目的地入口、盖章与分享
- 背景目录与资源声明
- 免费/付费访问策略所使用的 Journey 列表
- 内容品质 Agent 全目录报告
- 对应单元测试、契约测试与 Preview

只完成其中一部分不算“旅程开发完成”。

## 9. 代码质量要求

- 优先复用共享组件、Theme token、策略和目录。
- 不得使用复制粘贴形成多套近似逻辑。
- 复杂业务逻辑应移出 Widget，并提供纯函数或服务测试。
- 公共状态变化必须可恢复、可迁移并按 Journey 隔离。
- 对 iOS Safari、键盘、朗读、缓存和 Worker 回退等历史高风险区域，修改时必须增加或更新回归测试。
- 不得通过删除测试、降低断言、跳过质量 Gate 来让 CI 变绿。
- 注释应解释“为什么存在这个约束”，而不是复述代码。

## 10. 验证矩阵

### 10.1 所有代码变更

必须通过：

```bash
node --test worker/*.test.mjs
cd app
flutter pub get
flutter analyze
flutter test
flutter build web --release
```

若本地环境无法执行，必须依赖 PR CI 执行并检查每个步骤，不得仅报告“已提交”。

### 10.2 Journey 内容变更

除上述测试外，必须：

- 生成全目录内容品质报告
- 检查所有 Journey × Phoenix Lv.1–10
- `blocked = 0`
- `needsRevision = 0`
- 每个组合达到发布批准状态
- 在 PR 中保留质量报告证据

### 10.3 UI 与交互变更

必须验证：

- iPhone 尺寸与较矮视口
- 键盘打开与关闭
- 简体与繁体
- 降低动态效果模式
- Story、Discovery、词语弹层和返回续播
- Preview 真机或移动浏览器体验

### 10.4 发布与 Preview

必须确认：

- Agent tests 成功
- Flutter analyze 成功
- Flutter tests 成功
- Web build 成功
- Worker bundle 验证成功
- 内容品质 Gate 成功
- Preview 部署成功
- Preview health 返回当前 head commit
- PR 评论中的链接指向当前版本

## 11. 文档维护规则

- 产品原则变化：更新 `PRODUCT_PRINCIPLES.md`。
- UI 契约变化：更新 `UI_GUIDELINES.md`。
- 内容格式变化：更新 `STORY_GUIDELINES.md`。
- Gate 或阈值变化：更新 `CONTENT_QUALITY.md`。
- 里程碑变化：更新 `ROADMAP.md`。
- 可执行工作项变化：更新 `TODO.md`。
- 每个用户可感知或开发流程级变更：更新 `CHANGELOG.md`。
- Review 要求变化：更新 `REVIEW_CHECKLIST.md`。

不得在多个文件复制整段规则。其他文件应通过链接引用唯一来源。

## 12. 禁止事项

AI 不得：

- 直接合并 `main` 或在未询问 Founder 时批准合并
- 从过时 PR、旧 Preview 或旧 commit 开始新开发
- 修改产品原则却不更新文档
- 新增空壳 Journey、占位故事、通用干扰项或虚构来源
- 使用侵权图片、品牌角色、艺术家仿作或未授权字体
- 在客户端暴露 API Key、内部提示词或私人学习记忆
- 静默改变免费/付费规则、奖励经济或特别旅程价格
- 以不自然动效牺牲画面品质或性能
- 为通过测试而删除保护性测试
- 报告 Preview 成功而未检查部署与当前 commit

## 13. 完成定义

一项开发任务只有在以下条件全部满足时才算完成：

1. 功能与 Founder 要求一致。
2. 相关页面、目录、状态、内容和资产已完整同步。
3. 自动化测试与质量 Gate 通过。
4. PR head 已更新。
5. 独立 Preview 已验证并可访问。
6. 相关规范与 `CHANGELOG.md` 已同步。
7. 尚未合并 `main`，除非 Founder 已明确批准。
