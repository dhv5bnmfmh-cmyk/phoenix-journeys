# Phoenix AI Development Guide

> 状态：Phoenix 全项目最高级开发规范  
> 适用范围：Phoenix Journeys 全仓库、所有 AI、开发者与 Reviewer  
> 维护者：Founder 与项目维护者  
> 最后整理：2026-07-31

本文件是 Phoenix 开发的总规范入口。所有 AI 必须先读取本文件及同目录专项规范，再读取当前代码、测试、PR 与 Preview，最后开始开发。

当文档与代码不一致时，不得静默选择一方。必须判断哪一方代表 Founder 最新确认，并在同一变更中同步文档、代码与测试。

决策优先级：

1. Founder 当前任务中的最新明确决定
2. 本文件与 `PRODUCT_PRINCIPLES.md`
3. `UI_GUIDELINES.md`、`STORY_GUIDELINES.md`、`CONTENT_QUALITY.md`
4. 当前稳定代码与自动化测试形成的可执行契约
5. `ROADMAP.md` 与 `TODO.md`
6. `CHANGELOG.md` 中的历史记录

# 1. 项目目标

## 1.1 Phoenix 的使命

Phoenix 的使命是把语言学习变成一段可理解、可探索、可记住的文化旅程。

Phoenix 不只帮助 Explorer 记忆词语和语法，还要帮助其：

- 读懂真实、有来源的中文内容
- 理解地点、历史、文化与人的生活
- 在故事、发现、挑战和回忆中形成长期记忆
- 根据自身能力获得合适难度，而不是被统一教材推着走
- 在没有广告、焦虑和强迫留存的环境中持续学习

产品核心表达：

> 世界很大，从一门语言开始。

## 1.2 目标用户

首阶段目标用户是：

- 以越南语或英语为辅助语言的中文学习者
- 希望通过文化、故事和真实场景学习中文的人
- 需要简体与繁体支持的人
- 从初学者到高阶学习者，对应 Phoenix Lv.1–10
- 希望提升阅读、词汇、理解、表达、听读和跟读能力的人
- 重视移动端体验、短时学习和长期积累的人

首位 Founder Explorer 为 Toni。产品设计必须能服务真实学习需求，不得只为演示或截图而存在。

## 1.3 学习理念

Phoenix 采用以下学习理念：

1. 中文是主要学习内容，翻译只提供支持。
2. 先理解完整语境，再学习词语和结构。
3. 先产生好奇，再进入知识与练习。
4. 故事、单词、发现、挑战、回忆必须形成同一学习闭环。
5. 难度必须跟随学习者能力变化。
6. 反馈必须解释原因，而不是只给对错。
7. 错误是学习信号，不是惩罚。
8. 学习记录应自动保存，并形成可回顾的成长轨迹。
9. AI 只能增强学习，不得取代真实性、编辑判断和学习设计。
10. HSK 与 TOCFL 用于校准，不建立第二套互相冲突的等级系统。

## 1.4 产品定位

Phoenix 是移动优先的文化语言学习产品，不是：

- 普通背单词工具
- 单纯故事阅读器
- 旅游导览 App
- AI 聊天壳
- 游戏化金币收集器
- 考试题库复制品

Phoenix 的定位是：

- 以 Journey 为核心单位
- 以真实地点和文化主题建立记忆
- 以 Phoenix Lv.1–10 提供自适应内容
- 以地图、护照、盖章和回忆建立探索感
- 以 AI Agent 提供受约束、可解释的学习支持
- 以原创或合法授权视觉资产建立高品质体验

## 1.5 长期规划

长期发展顺序：

1. 稳定中文 Journey 核心体验。
2. 建立可持续扩张的普通与特别 Journey 内容体系。
3. 完成词汇、挑战、跟读和弱项复练闭环。
4. 完成账户、同步、付费容量与隐私治理。
5. 建立成熟的 AI 内容生产与审核系统。
6. 在中文体系成熟后扩展其他语言与世界文化 Journey。

任何远期扩张都不得牺牲当前中文体验、真实性或移动端稳定性。

# 2. 开发原则

所有开发必须遵守以下原则：

1. 保持产品、代码、数据和视觉一致性。
2. 不随意修改 Founder 已确认的功能。
3. 不降低现有体验来换取更快完成。
4. 不增加没有明确学习价值的复杂度。
5. 不破坏已有学习流程、进度或数据。
6. 修改一处必须检查所有相关页面、服务、目录和测试。
7. UI、动画、文案、字体、颜色和交互必须统一。
8. 先复用共享组件和规则，不建立平行系统。
9. 先解决根因，不用局部补丁掩盖结构问题。
10. 保持移动端优先，尤其是 iPhone 与 Safari。
11. 保持简体、繁体、拼音、越南语和英语一致。
12. 保持 Journey ID、地图、护照、背景、来源和存储绑定一致。
13. 不删除测试、不降低断言、不绕过质量 Gate。
14. 不直接修改 `main`。
15. 不自动合并 `main`，只有 Founder 明确批准后才可合并。
16. 发现新最佳实践时必须更新文档，不只更新代码。
17. 发现非阻断改进时记录到 `TODO.md`，避免无边界扩张。
18. 对历史高风险区域必须补充回归测试。
19. 不把聊天记忆当作唯一需求来源。
20. 不把兼容字段或旧代码误认为当前产品方向。

## 2.1 固定产品契约

当前公开 Journey 流程固定为：

1. 故事
2. 单词
3. 发现
4. 挑战
5. 回忆
6. 完成与盖章

“思考”和“表达”不得恢复为公开 Journey 步骤。跟读训练保持独立页面。

Phoenix Lv.1–10 是唯一统一的用户等级控制。HSK 与 TOCFL 只用于内容校准与设置参考。

# 3. 开发流程

所有任务必须按以下流程执行：

```text
Review
  ↓
Plan
  ↓
Implement
  ↓
QA
  ↓
Challenge
  ↓
Preview
  ↓
Merge
```

## 3.1 Review

开发前必须：

- 读取本文件和所有相关专项规范
- 读取当前 PR、head branch、head commit
- 读取相关代码、测试、数据目录与工作流
- 确认当前批准基线
- 检查现有功能是否已经实现部分需求
- 识别所有受影响页面和系统
- 识别历史回归风险
- 确认不触碰未授权范围

## 3.2 Plan

计划必须说明：

- 用户目标
- 最小完整变更范围
- 受影响文件和功能
- 数据、状态与迁移影响
- 测试与 QA 方法
- Preview 验证路径
- 可能风险与回滚方式

计划应追求完整，但不得制造不必要架构。

## 3.3 Implement

实现时必须：

- 使用当前开发分支
- 复用共享组件、Theme、目录和服务
- 同步代码、数据、测试与文档
- 保持旧数据兼容
- 保持 Journey 全系统接入
- 按可验证单元提交
- 不混入无关修改

## 3.4 QA

QA 必须覆盖：

- 自动测试
- 静态分析
- Web build
- Worker bundle
- 移动端布局
- 简繁与多语言
- Journey 流程
- 状态恢复
- 朗读与高亮
- 内容品质
- 图片与动画
- Preview 部署

## 3.5 Challenge

这里的 Challenge 是开发红队检查，不是 Journey 内的学习挑战。

AI 必须主动尝试推翻自己的实现：

- 哪些地方只是表面完成？
- 哪些页面未同步？
- 哪些规则可能冲突？
- 哪些状态会在退出、刷新或切换后损坏？
- 哪些内容有 AI 套话或重复？
- 哪些图片、动画或文案显得廉价？
- 哪些测试只覆盖成功路径？
- 哪些改动增加了复杂度却没有学习价值？
- 哪些问题在低等级、繁体、iPhone 或 Safari 才出现？
- 哪些地方距离正式版仍有差距？

发现阻断问题必须修复后重新执行 QA。

## 3.6 Preview

Preview 必须：

- 使用独立 PR Worker
- 基于 feature head commit
- 携带当前 commit 版本
- 通过健康检查
- 不覆盖 `main` 或其他 PR
- 提供全开放体验入口
- 完成移动端主要路径体验
- 保留质量报告与 CI 证据

## 3.7 Merge

只有满足以下条件才进入 Merge：

- 自动 Review 通过
- 自动 QA 通过
- Challenge 红队检查通过
- Preview 成功
- 内容品质达到发布标准
- 文档与代码同步
- Founder 已体验当前 Preview
- Founder 明确同意合并 `main`

没有 Founder 明确批准，不得执行 Merge。

# 4. 内容规范

## 4.1 故事规范

- 每个新 Journey 必须有完整基础故事母版。
- 基础母版默认由 4 个可追踪 section 组成。
- 每个 section 必须有稳定 ID 与来源 ID。
- 故事必须有开场、发展、变化和收束。
- 自适应改写必须保留开场场景与结尾意义。
- 故事必须与目的地或主题紧密相关。
- 不得虚构事实、日期、人物、引语或来源。
- 传说、争议和 Phoenix 原创必须明确标注。
- 中文、拼音、越南语和英语顺序必须对齐。
- 不得出现空泛励志结尾、机械四段式或模板化 AI 文风。

## 4.2 短文规范

短文包括等级适配后的阅读段落、挑战上下文、学习摘要和其他短篇学习内容。

- 必须有完整主题和逻辑，不得只是故事截断。
- 长度、词汇和句法必须符合当前 Phoenix Level。
- 必须保留必要的人物、地点、时间与因果关系。
- 段首不得使用没有指代对象的依赖词。
- 不得堆积关键词或用通用 filler 补长度。
- 不得与其他 Journey 只替换地名后复用。
- 必须能独立朗读、理解和用于学习任务。
- 高级短文必须提高篇章与语义复杂度，而不是只增加生词。

## 4.3 发现页规范

- 每条发现必须提供故事之外的新知识。
- 运行时每个等级显示 1 至 2 条批准内容。
- 发现内容可包括历史背景、空间设计、文化意义、工艺、生活或争议说明。
- 不得重复故事，也不得在发现之间重复。
- 每条必须有中文、拼音、简明中文、越南语和英语。
- 不得把传说写成确定事实。
- 不得出现无来源的精确数字和断言。
- 发现页应帮助 Explorer 从“故事印象”进入“真实理解”。

## 4.4 挑战规范

固定三种模式：

1. 短文复原
2. 语病修复
3. 补回句子

规则：

- 每种模式固定 4 个平衡候选答案。
- 每种模式最多 3 次机会。
- 第 1 次正确奖励金币。
- 第 2 次正确奖励银币。
- 第 3 次正确奖励铜币。
- 三次未正确奖励碎银并展示正确答案。
- 错误选项必须可信、主题相关、长度平衡。
- 提示必须逐步增加，不可直接泄露答案。
- 讲解必须包含训练目标、原因、规则和记忆方法。
- 弱项复练不得重复发放奖励。
- 难度必须随 Phoenix Level 调整。
- 挑战不得只靠关键词匹配，应检查逻辑、语法和篇章理解。

## 4.5 生词规范

- 新普通 Journey 的基础词表不少于当前批准规格。
- 词语必须来自故事或发现。
- 不得重复、凑数或选择与主题无关的词。
- 每个词必须包含：词语、拼音、词性、简明中文、母语解释、英语解释。
- 多义词必须使用当前语境义项。
- 例句必须自然并真实包含目标词。
- 专名、多音字和声调必须人工或规则复核。
- 单词卡必须保持可读，词少时缩小并保持透明层次。
- 保存、朗读、详情和例句必须同步工作。

## 4.6 图片规范

- 图片必须服务当前 Journey、页面阶段和学习内容。
- 必须原创、项目自有或拥有合法授权。
- 不得使用品牌角色、商标、水印或未经许可的风格仿作。
- 不得有低清拉伸、灰柱、错误裁切或压缩损坏。
- AI 图片必须检查建筑、人物、手指、文字、服饰、文化符号和空间逻辑。
- 背景必须为正文保留可读区域。
- 特别 Journey 图片必须与故事场景对应。
- 目的地背景应有足够场景变化，但不能为了数量加入无关图。
- 图片替换必须同步资源目录、映射、缓存、测试与授权记录。

## 4.7 动画规范

- 动画必须服务抵达、理解、反馈、转场或完成。
- 不得为了“看起来高级”加入无意义动效。
- 地图路线、缩放和落点必须符合真实空间逻辑。
- 动画不得闪烁、突跳、抖动正文或制造假水波。
- 不使用廉价粒子、外露调试图形、加号或无意义圆圈。
- 动画必须可中断、可恢复，并避免重复播放。
- 必须支持降低动态效果。
- 动效失败时应优雅降级为高质量静态画面。
- 动画不能阻塞主要学习操作或降低可读性。

# 5. 内容质量标准

Phoenix 使用 10 个维度进行评分，每项 10 分，总分 100 分：

1. 真实性与来源
2. 学习价值
3. 故事与篇章质量
4. 词汇与语言准确性
5. HSK 适配
6. TOCFL 适配
7. 多语言支持
8. UI、图片与动画表现
9. 原创性、重复率与 AI 痕迹
10. 技术接入与状态完整性

## 5.1 星级定义

### ★★★★★ 正式版品质

- 总分 95 至 100
- 无真实性、版权、流程、数据、隐私或发布阻断项
- 所有自动测试、质量 Gate 和 Preview 通过
- 无明显 AI 痕迹或跨 Journey 重复
- UI、图片、动画、文案和学习价值统一
- 可以进入 Founder 正式验收与合并评估

### ★★★★☆ 高质量 Preview

- 总分 85 至 94
- 核心功能完整，无 P0 阻断
- 可能存在少量可见细节、内容自然度或边界体验问题
- 可供 Preview 体验，但不能直接视为正式版完成
- 必须列出并修复剩余 P1 项后才能合并

### ★★★☆☆ 可运行但需要重做

- 总分 70 至 84
- 主路径可能可用，但存在明显不一致、重复、AI 套话、适配不足或视觉问题
- 不允许合并 `main`
- 必须回到 Plan 或 Implement 阶段修复

### ★★☆☆☆ 不合格

- 总分 50 至 69
- 多个核心维度不达标
- 可能缺少来源、页面同步、移动端适配或测试
- 禁止发布 Preview 给 Founder 验收

### ★☆☆☆☆ 阻断

- 总分低于 50，或存在任意一票否决问题
- 包括虚构事实、侵权资产、数据破坏、隐私泄露、流程损坏、无法构建或错误部署
- 必须立即停止发布并修复根因

## 5.2 一票否决项

以下任何一项出现，即使总分较高也不得达到五星：

- 虚构或无法验证的核心事实
- 未授权图片、字体、音乐或品牌资产
- 丢失用户进度、盖章、奖励或学习记录
- 破坏固定 Journey 流程
- 暴露密钥或私人学习内容
- 自动合并 `main`
- CI、质量 Gate 或 Preview 失败
- 明显低清、严重生成瑕疵或不可读 UI
- HSK/TOCFL 等级严重错配
- 复制其他 Journey 或出现高重复内容

## 5.3 发布门槛

- 内部开发中间态可以低于四星，但不得对外宣称完成。
- Founder Preview 至少达到四星，并明确剩余问题。
- 合并 `main` 必须达到五星。
- 内容目录发布必须满足 `blockedCount = 0`、`needsRevisionCount = 0`。

# 6. AI 审核流程

每次开发完成后，AI 必须执行以下审核。

## 6.1 故事审核

检查：

- 事实与来源
- 结构、开场和结尾
- 等级长度与段落
- 语言自然度
- 传说与原创标注
- 与其他 Journey 的重复
- AI 套话与模板感

## 6.2 图片审核

检查：

- 主题相关性
- 版权与授权
- 分辨率与裁切
- 建筑、人物、文字和文化细节
- 背景可读性
- 生成瑕疵
- 与故事场景一致性

## 6.3 动画审核

检查：

- 是否有明确目的
- 路线与空间逻辑
- 流畅性
- 可中断与恢复
- 降低动态效果
- 是否闪烁、突跳或显得廉价
- 是否阻塞学习

## 6.4 UI 审核

检查：

- PhoenixTheme 一致性
- iPhone 窄屏与矮屏
- 键盘安全
- 文本可读
- 简繁一致
- 控件状态
- 空、错、加载和重试
- 可访问性

## 6.5 代码审核

检查：

- 架构与单一来源
- 状态隔离和迁移
- 共享组件复用
- 边界与错误处理
- 回归风险
- 测试覆盖
- Worker 与密钥安全
- Preview 部署契约

## 6.6 学习价值审核

检查每个新增元素是否：

- 帮助理解
- 帮助记忆
- 帮助应用语言
- 提供新文化知识
- 对当前等级合适
- 值得占用用户时间

没有学习价值的功能、动画或文案应删除，而不是保留装饰。

## 6.7 AI 痕迹审核

重点寻找：

- 重复句式
- 机械四段结构
- 空泛形容词
- 无来源的具体细节
- 过度对称的文案
- 每段相同节奏
- 通用励志收尾
- 生硬翻译
- 不自然的按钮文案
- 只替换地名的模板内容

## 6.8 重复率审核

必须比较：

- 同一 Journey 内故事与发现
- 不同发现之间
- 不同等级之间
- 不同 Journey 之间
- 词语与例句
- 挑战选项
- UI 文案与提示

不得只比较完全相同文本，还要识别语义重复和模板替换。

## 6.9 HSK 适配审核

检查：

- 词汇频率与等级
- 句法复杂度
- 句子长度
- 篇章连接
- 阅读任务负荷
- 提示难度
- 产出要求
- 高阶内容是否真正提升语言能力

## 6.10 TOCFL 适配审核

检查：

- 繁体显示与词形
- 台湾常见语体差异
- 词汇频率
- 阅读长度
- 篇章理解
- 书面与口语平衡
- 文化专名
- 与 Phoenix Level 的映射一致性

## 6.11 审核结果

每次审核必须输出：

- 星级与总分
- 一票否决项
- P0 阻断项
- P1 合并前必须修复项
- P2 可进入 TODO 的提升项
- 已自动修复内容
- 仍需 Founder 决策的事项

# 9. 每次开发必须遵守

开发完成以后，AI 不能因为“代码已写完”就停止。

必须继续完成以下闭环：

1. 自动 Review。
2. 自动 QA。
3. 自动执行 Challenge 红队检查。
4. 自动寻找当前任务范围内还能提升的地方。
5. 自动修复 P0 与 P1 问题。
6. 修复后重新执行测试、质量审核和 Preview。
7. 更新相关规范、TODO、Roadmap 或 Changelog。
8. 直到达到当前发布阶段要求。

## 9.1 “继续优化”的边界

继续优化不等于无限扩功能。

必须继续优化：

- 当前任务造成或暴露的质量问题
- 当前任务涉及页面的一致性问题
- 会阻断正式版的移动端、内容、数据、隐私或测试问题
- 可以低风险明显提升正式版品质的问题

不得自行扩展：

- 未经批准的新产品模块
- 与当前任务无关的大型重构
- 新货币、新商业规则或新社交系统
- 改变固定 Journey 流程
- 自动合并 `main`

当当前范围达到五星，且剩余问题均为非阻断 P2 时：

- 将 P2 写入 `TODO.md`
- 更新 `CHANGELOG.md`
- 发布当前 commit 的 Preview
- 向 Founder 报告 PR、commit、质量结果和体验链接
- 保持 Draft，等待后续开发或合并决定

## 9.2 文档同步规则

以后所有 AI 必须：

1. 先读取这些文档。
2. 再读取当前代码、测试、PR 和 Preview。
3. 最后开始开发。
4. 发现新的最佳实践时更新对应文档。
5. 不得只更新代码。
6. 保持文档、代码、测试和产品行为同步。
7. 删除过时规则，合并重复规则。
8. 将历史事实放入 `CHANGELOG.md`，不要混入长期原则。
9. 将阶段方向放入 `ROADMAP.md`。
10. 将可执行未完成项放入 `TODO.md`。

## 9.3 完成定义

只有同时满足以下条件，任务才可报告为完成：

- 用户要求完整实现
- 所有相关页面和功能同步
- 自动测试与构建通过
- 内容、图片、动画、UI、代码和学习价值审核通过
- AI 痕迹与重复率已检查
- HSK 与 TOCFL 适配已检查
- Challenge 红队检查无 P0/P1
- 当前阶段星级达标
- Preview 已部署且对应当前 commit
- 文档已同步
- 未合并 `main`

本文件与 `PRODUCT_PRINCIPLES.md`、各专项规范、Roadmap、TODO、Checklist 和 Changelog 共同构成 Phoenix 的唯一开发标准。
