# Phoenix Story Library Rules

> Story System Version：`1.0.0`  
> 状态：全故事库强制规范  
> 最后整理：2026-08-01

Phoenix Story Library 必须像一本经过总编辑统筹的正式故事书。单篇优秀但全库重复，仍然不合格。

## 1. 当前基线

- 普通 Journey：32
- 特别 Journey：9
- 正式故事母版：41
- 每篇母版：4 个 section、4 组中拼越英阅读支持
- Phoenix Lv.1–10：10 个等级
- 运行时检查组合：410

数量从统一目录读取。本文只记录 Story System v1.0.0 的审稿快照，不作为运行时硬编码来源。

## 2. 作品集目标

整个故事库必须同时具备：

- 城市、自然、遗产、工艺、社区、技术、家庭、伦理、神话与文学的平衡
- 儿童、少年、成人与非人角色的适度变化
- 寻找、调查、争论、修复、表演、记录、协商、选择、照护等不同动作
- 喜剧、悬疑、现实、抒情、奇谈、伦理困境等不同气质
- 封闭、开放、回环、关系修复、公开承担、保留未知等不同结尾

不得让 Phoenix 越扩张越像同一篇文章的 41 次换皮。

## 3. 重复率

必须检查：

- 中文全文相似度
- 连续句子或固定短语重复
- 开场前 80 字相似度
- 结尾后 80 字相似度
- Lv.7–10 新增短文相似度
- Discovery 与 Story 重复率
- Challenge 语境与干扰项重复

自动门槛沿用 `JourneyLiteraryQualityAuditor` 与 `STORY_QUALITY_GATE.md`。发现新的模板趋势时，应新增检测，而不是只修一篇。

## 4. 人物重复

全库人物检查维度：

- 年龄
- 性别表达
- 家庭关系
- 职业或学习身份
- 性格缺陷
- 目标
- 权力位置
- 与城市或文化的关系
- 说话方式
- 最终承担

禁止连续出现：

- 自信孩子犯错后被老师纠正
- 小记者或小研究员调查真相
- 老人负责解释全部文化
- 主角从自私变无私
- “你”陪同主角完成相同任务

同类身份可以再次出现，但必须拥有不同欲望、冲突、语言和结局。

## 5. 城市重复

同一城市或同类遗产不得只换景点。

必须检查：

- 空间结构是否不同
- 城市生活是否不同
- 文化机制是否不同
- 人物与地点的关系是否不同
- 学习主题是否不同

例如宫殿类故事不能都写“观察中轴并理解修复”，水景类不能都写“放慢脚步看倒影”，古城类不能都写“寻找旧地址”。

## 6. 剧情重复

记录每篇的剧情引擎：

- 寻物
- 送达
- 比赛
- 争论
- 调查
- 修复
- 排演
- 公共决策
- 家庭关系
- 规则困局
- 证词冲突
- 伦理选择
- 记录与版权

新增故事若与现有故事共享“任务、阻碍、高潮、结尾”中的三项，视为中等问题，必须重构。

## 7. 情绪重复

全库不能只有：

```text
自信 → 犯错 → 理解 → 成长
```

必须平衡：

- 焦虑到承担
- 好胜到合作
- 怀疑到求证
- 害怕到识别操纵
- 执着到接受变化
- 羡慕到创造新方法
- 想控制到尊重未知
- 追求华丽到让当事人讲述
- 想占有到建立公共边界
- 理想化到接受复杂记忆

情绪变化必须由事件推动。

## 8. 句型重复

建立全库高风险词表并持续维护：

- 不只是……而是……
- 真正……的是……
- 终于明白
- 共同形成
- 过去与今天
- 继续走向未来
- 让文化焕发
- 一幅……画卷

同一连接方式、对话结构、比喻和结尾句连续出现时，即使单篇自然，也要从全库角度调整。

## 9. 教育意义重复

Phoenix 不把所有故事变成同一堂道德课。

教育价值应分布在：

- 证据与诚实
- 协商与公共空间
- 责任与后果
- 多种解释共存
- 文化边界
- 社区许可与署名
- 风险与创造力
- 传统与现代使用
- 家庭沟通
- 对未知保持克制
- 观察与验证
- 语言和多文化理解

“保护文化遗产”不能成为默认结论。

## 10. 世界观冲突

### 普通 Journey

- 真实世界遵守历史、地理、技术和社会事实。
- 不使用无法解释的魔法推动现实遗产故事。
- 传说出现时必须标注，并不取代事实。

### 特别 Journey

- 每个世界有独立异常规则。
- 异常不能无代价地解决问题。
- 不同特别 Journey 不共享同一万能神秘体系。
- Phoenix 原创角色不能冒充原典人物或史实。

## 11. 文化冲突

全库检查：

- 是否把少数民族、宗教、地方传统或跨文化历史写成异国风装饰
- 是否由外来主角替当地人定义文化
- 是否把复杂历史简化成“融合很美好”
- 是否忽略当代社区的真实使用和争议
- 是否把保护与发展写成单一正确答案

出现文化冲突时，优先补充来源和当事人视角，不用一句平衡口号掩盖。

## 12. 整体平衡

每批新增前，必须统计：

- 普通与特别 Journey 比例
- 城市、自然、建筑、工艺、生活、文学与神话比例
- 主角身份分布
- 冲突类型分布
- 情绪曲线分布
- 高潮动作分布
- 结尾类型分布
- 主要意象分布
- 学习价值分布
- HSK／TOCFL 阅读负荷分布

若新批次加剧单一倾向，必须调整选题或故事引擎。

## 13. 短文库规则

Lv.1–10 短文属于故事库，不是技术生成副产品。

必须：

- 保留同一人物、目标、冲突和结尾。
- 高等级新增句必须属于当前故事。
- 不使用共享城市观察段落补长度。
- 特别 Journey 使用专属类型扩展链。
- 任意等级都能独立朗读和理解。
- 全等级进行跨故事相似度与固定短语检查。

## 14. Story 与其他页面的作品集一致性

全库还要检查：

- 生词是否集中在同类抽象词
- Discovery 是否反复讲“历史与现代”“保护与传承”
- Challenge 是否反复使用相同语病和干扰逻辑
- 回忆提示是否都问“你学到了什么”
- 盖章是否能区分不同经历

## 15. 修改一篇时的强制范围

修改任一故事后必须：

1. 检查全库人物矩阵。
2. 检查全库剧情矩阵。
3. 检查全库情绪与结尾矩阵。
4. 检查相邻至少五篇故事。
5. 检查同城市、同类型、同教育主题故事。
6. 重新生成 Lv.1–10。
7. 检查 Story、单词、Discovery、Challenge、回忆与盖章。
8. 运行全库自动 Gate。

如果修改使其他故事显得相似，必须同步调整相关故事。

## 16. 新增一批时的强制范围

- 先提交矩阵缺口，再选择题材。
- 一批内部不得共享同一结构。
- 新增数量不得超过当前人工总编辑能够完整横向审核的范围。
- 新 Journey 必须在同一 PR 中完成全部系统接入。
- 质量不足时宁可减少数量，不用模板补齐批次。

## 17. 维护与发布

- 矩阵记录在 `CONTENT_VARIETY_GUIDE.md`。
- 规则变化同步 auditor、测试、质量报告和 Changelog。
- 自动 Gate 通过后仍执行总编辑人工复审。
- 故事库 severe = 0、medium = 0 才能发布 Preview。
- 合并 `main` 只由 Founder 明确批准。
