# Phoenix UI Guidelines

> 状态：规范性文件  
> 适用范围：Flutter UI、交互、动效、图片、朗读与移动端适配  
> 最后整理：2026-07-31

Phoenix 的 UI 应像一本会呼吸的旅行护照：背景负责带人进入地点，界面负责让学习动作清楚、稳定、毫不费力。视觉效果不能抢走语言学习的方向盘。

## 1. 核心原则

1. **移动优先**：先保证 iPhone 窄屏和矮屏，再扩展大屏。
2. **一屏完成主要动作**：每个主步骤在一个稳定页面框架中完成，不使用横向分页。
3. **内容优先**：背景、动效和装饰不得降低文字、按钮、朗读进度与反馈的可读性。
4. **统一系统**：颜色、字体、面板、按钮和间距必须优先使用 `PhoenixTheme` 与共享组件。
5. **真实克制**：地图、地理、文化与动态效果必须可信；宁可使用高质量静态图，也不使用廉价或不自然动画。
6. **状态可恢复**：离开页面、打开弹层、切换语速或重新进入时，用户不应失去进度。

## 2. Journey 公开流程

公开步骤固定为：

1. `故事`
2. `单词`
3. `发现`
4. `挑战`
5. `回忆`
6. `完成`

- 顶部进度组件使用同一组标签。
- Journey 未完成前，只能进入当前、上一步或下一步；不得任意跳过。
- Journey 完成后可以回看已解锁步骤。
- “思考”和“表达”不得重新出现在主流程、步骤条或导航中。
- 跟读训练必须保持独立导航入口。

## 3. 页面布局

### 3.1 一屏规则

- 主页面不得使用水平 `PageView` 或横向滑动切换学习步骤。
- 顶部 AppBar、进度、主要内容和底部行动按钮应保持稳定位置。
- 内容过长时，可以在**受约束的内容区内部**垂直滚动，不能让整页结构漂移。
- Story 与 Discovery 应优先通过等级内容长度、字体适配和紧凑间距控制在同一屏幕框架。
- 不得为固定卡片高度截断文字；可以缩小卡片、字体或内部间距，但信息必须完整可访问。

### 3.2 底部行动区

- 主行动使用 Phoenix 红色 Filled Button。
- 次行动使用 Outlined Button。
- 返回、次行动、继续按钮应处于同一稳定区域。
- 按钮文字必须单行，必要时使用合理缩写或更短文案，不得出现两行挤压。
- 加载状态必须禁用重复提交并显示明确进度。

### 3.3 AppBar

- Journey 标题保持紧凑。
- Phoenix 等级控制固定在右上角。
- 简繁切换应随时可用，但不能遮挡标题或等级。
- 不增加与当前步骤无关的大型操作。

## 4. 视觉系统

### 4.1 颜色

当前核心色：

- Phoenix Red：`#9D1C20`
- Phoenix Gold：`#C79A43`
- Ink：`#202124`
- Paper：`#F8F2E8`
- Translation：`#476C8B`
- AI：`#6A4C8C`

禁止在 Journey 页面自行发明相近红、金、玻璃面板或阴影。需要新 token 时，应先加入 `PhoenixTheme`，再由组件使用。

### 4.2 字体

Phoenix 只保留两类字体角色：

1. **展示字体**：标题、旅程名、重点视觉文字，使用中文书写感 serif / 楷体回退链。
2. **阅读字体**：故事、拼音、拉丁文字、解释、按钮和元数据，使用清晰 sans-serif 回退链。

规则：

- 中文正文不得使用装饰字体。
- 拼音、越南语和英语必须使用阅读字体。
- 字体文件必须有合法授权；不得向用户分发仓库外字体文件。
- 简体和繁体都必须在回退链中可读。

### 4.3 面板

- Journey 内卡片使用共享 `journeyPanelDecoration`。
- 写作或回忆输入使用共享高对比写作面板。
- 单词详情使用不透底的金色实心面板，避免背景图和词网格穿透。
- 面板应尽量紧凑、透明并保留背景层次，但不能牺牲对比度。
- 同一页面不得混用多套圆角、边框与阴影语言。

## 5. 背景与图片

### 5.1 资产要求

- 必须原创、项目自有或拥有清晰授权。
- 禁止品牌角色、商标、未经许可的影视或游戏 IP。
- 禁止模仿在世艺术家的独特风格。
- 优先使用高分辨率竖屏 WebP。
- 构图必须为顶部 AppBar、中央正文和底部按钮预留安全区域。
- 不得出现灰柱、低清拉伸、异常边缘、外露加号、圈线、水印或闪烁。

### 5.2 目的地背景库

- 每个已发布目的地规划 10 个经过审查的离线背景位置。
- 资源目录、`pubspec`、背景映射和测试必须同步。
- 背景不能在 Explorer 运行时依赖付费图片 API。
- 缺失资源必须明确回退到项目自有默认背景，不能显示破图。

### 5.3 特别 Journey 图片

- 每个特别 Journey 保留 10 个有效故事场景位置，包括已批准主图。
- 图片必须与故事情节一致，不使用与普通城市无关的通用幻想图。
- 如果动效看起来不真实，必须改为高清静态图或轻量淡入切换。

## 6. 动效

- 动效用于建立空间感、到达感和反馈，不用于炫技。
- 优先使用慢速、低成本、可循环的图层位移、景深和淡入。
- 禁止高频闪烁、廉价粒子、假水波线、无意义漂浮物和遮挡正文的装饰。
- 动态背景不得造成文字位置、按钮几何或朗读指示抖动。
- 所有动效必须支持系统“降低动态效果”。
- 降低动态效果时，保留状态变化，移除非必要移动。

## 7. 世界地图与抵达体验

- 世界地图与城市地图必须使用项目自有高清图。
- 飞机路径应遵循真实地理方向和每座城市的校准坐标。
- 抵达序列为：世界视角 → 航线推进 → 城市放大 → 从上方进入落点 → 显示目的地选择。
- 同一次进入不重复播放完整飞行。
- 飞机使用项目自有高清图形，不使用低清系统图标。
- 抵达后只显示该城市的目的地，不得混入其他城市。
- 地图热点应可点击、可辨识并提供清晰状态，不依赖颜色 alone。

## 8. 护照

- 使用透明、有层次的地图作为主要结构。
- Journey 按城市分组，通过地图热点或城市入口打开。
- Journey tile 必须紧凑，重点只保留旅程名和小盖章。
- 不恢复占据大量空间的总览卡、左侧列表或厚重方框。
- 已获得盖章与未完成状态必须清楚区分。
- 盖章动效应模拟真实落印：实体印章短暂出现，随后消失，透明印记保留在背景右上区域。
- 特别 Journey 使用独立、高辨识度、钱包感知的入口，不与普通格子混淆。

## 9. Story 与 Discovery

- 朗读播放器保持紧凑，不能挤占正文主要区域。
- 中文正文使用高对比白色和统一阴影。
- 当前朗读位置只通过文字高亮表达，不增加独立色条、整段背景或跳动三角装饰。
- 尚未朗读的文字可以保持布局占位，但必须不可点击、不可选择并视觉隐藏。
- 用户手动滚动时，自动跟随暂时停止，并提供明确恢复跟随动作。
- Story 与 Discovery 必须共享相同点词、释义、朗读和高亮组件。
- Discovery 提供新知识，不应只是 Story 的重复版。

## 10. 单词页与词语详情

### 10.1 单词网格

- 当前手机布局使用 3 列网格。
- 网格填满可用高度，不设置固定卡片数量上限。
- 卡片数量较少时，卡片和面板应缩小并保持透明，不要拉伸成大块。
- 卡片优先级：中文词、拼音、词性、Explorer 母语解释、英语解释；空间足够时再显示中文解释。
- 已保存状态必须清楚但不抢占词语主体。

### 10.2 词语详情

- 弹层高度跟随内容并限制最大屏幕占比。
- 必须支持上一词、保存、下一词，并尽量保持在同一行。
- 显示中文、拼音、词性、简明中文、母语、英语和真实例句。
- 打开弹层前如正在朗读，应暂停并记录位置；关闭后从同一位置继续。
- 朗读重建不得自动关闭已经打开的词语详情。

## 11. 挑战页面

- 固定三种模式：短文复原、语病修复、补回句子。
- 固定四个候选答案；任何数量调整都需要 Founder 决定并同步测试。
- 候选答案使用统一最小视觉高度，不截断完整答案。
- 选项长度应平衡，错误选项必须唯一、可信且与 Journey 主题相关。
- 每题最多三次机会，提交按钮显示当前次数。
- 第一次与第二次错误后显示逐级提示；第三次后展示正确答案并进入讲解。
- 讲解必须包含训练目标、掌握状态、正确答案、原因和记忆方法。
- 三项结束后显示 Journey 学习总结，并允许重练最弱项。
- 弱项复练不得重复发放奖励。

## 12. 回忆与输入页面

- 回忆是主流程中唯一公开写作步骤。
- 输入区域必须始终保持高对比，不受背景图颜色影响。
- 使用持久 `FocusNode`，不得在 rebuild 时丢失焦点。
- 键盘打开时页面必须 resize；隐藏固定底部导航，避免遮挡输入。
- 不使用合成“点击空白处”强制关闭 Safari 键盘。
- 键盘模式应保持主要输入与提交动作可见。

## 13. 朗读与声音

- 音频、进度、字词高亮与继续位置共享一个 Controller offset。
- 默认语速为 `1.0x`。
- 可选范围 `0.5x` 至 `1.5x`，步进 `0.1x`。
- 语速变化必须先安全暂停，再从相同位置继续。
- Voice picker 按语言区域排序自然声音并记住选择。
- 打开 Voice picker 不得破坏当前播放状态。
- 词语、注释或辅助语言的临时朗读结束后，应恢复原 Journey 位置。
- 播放失败时必须显示明确重试，不得停留在假“播放中”。
- Story 与 Discovery 的已保存位置相互独立。
- 恢复页面时只准备暂停状态，不未经用户手势自动播放。

## 14. 简体、繁体与多语言

- 所有 Explorer 可见中文必须经过统一 script conversion。
- 页面、导航、错误、加载、挑战和分享文案不得出现简繁混用。
- 内容源默认维护规范中文文本，运行时统一转换，不保存两套漂移副本。
- 母语当前默认支持越南语，英语始终作为第二辅助解释。
- 翻译是辅助，不能压过中文正文。

## 15. 可访问性与性能

- 重要信息不能只靠颜色传达。
- 图标按钮必须有 tooltip 或语义标签。
- 触控区域应满足移动端可点击尺寸。
- 对比度必须在最亮与最暗背景上都可读。
- 朗读不是唯一信息通道，所有内容必须有文字。
- 动效、阴影和模糊层数必须考虑 iPhone Flutter Web 性能。
- 不因装饰持续触发全页 rebuild。
- 图片必须压缩并避免不必要的超大纹理。

## 16. UI 完成定义

UI 变更完成前必须确认：

- 与 `PhoenixTheme` 和共享组件一致
- iPhone 窄屏、矮屏无溢出
- 键盘不遮挡输入和按钮
- 简体、繁体均正确
- 降低动态效果可用
- 朗读、进度和高亮同步
- 页面返回与重进状态可恢复
- 无横向分页或不必要滚动
- 背景、字体和图标拥有合法来源
- Preview 真机体验通过
