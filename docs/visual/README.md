Version: 1.0.0

Priority: ★★★★★ (Highest)

---

# 1. Purpose

Phoenix Visual System（简称 PVS）是 Phoenix 中所有视觉资源（Visual Assets）的唯一正式规范体系。

Visual System 并不是：

- 图片资源目录。
- UI 设计稿集合。
- 动画规范合集。

Visual System 是 Phoenix 的正式视觉架构（Visual Architecture）。

它定义：

- Phoenix 为什么这样设计视觉。
- Phoenix 的整体视觉风格。
- 图片如何生成。
- Journey 如何建立视觉。
- 动态背景如何设计。
- 动画如何服务阅读。
- 图片如何审核。
- 图片什么时候允许进入正式版。

Visual Documentation 是所有视觉工作的唯一依据。

任何视觉资源，都必须遵守本 System。

---

# 2. Why Visual System Exists

Phoenix 不是展示 AI 绘图能力。

Phoenix 的视觉，也不是为了追求最华丽。

Phoenix 的视觉存在只有一个目的：

**服务阅读。**

故事创造世界。

视觉帮助进入世界。

学习发生在世界里面。

如果视觉抢走故事。

视觉就是失败。

如果视觉影响阅读。

视觉就是失败。

如果视觉影响学习。

视觉就是失败。

因此：

Phoenix 将 Visual 建立为独立 Professional System。

让所有图片、背景、动画、Journey、地图、护照、Banner、Loading、Splash 与 UI 插画，都拥有统一标准。

每一个 Journey。

拥有自己的视觉世界。

---

## Goal Three

保证：

视觉始终服务：

阅读。

学习。

探索。

而不是：

展示特效。

---

## Goal Four

建立长期可维护的：

Visual Documentation。

让未来所有 AI。

都能持续扩充 Phoenix。

而不是重新设计 Phoenix。

# 11. Relationship with Other Systems

Visual 是 Phoenix Professional Systems 的视觉表达层。

Visual 不独立存在。

Visual 必须与其它系统协同工作。

---

## Visual × Story

Story 定义：

世界。

人物。

文化。

Journey。

Visual 表现：

世界。

人物。

文化。

Journey。

Visual 不改写 Story。

Story 不规定视觉实现。

---

## Visual × Learning

Learning 决定：

学习流程。

Visual 决定：

学习体验中的视觉呈现。

Visual 不增加学习内容。

Learning 不设计图片。

---

## Visual × UI

UI 定义：

交互。

布局。

组件。

Visual 定义：

视觉语言。

配色。

背景。

图像。

UI 与 Visual 必须共同形成统一体验。

---

## Visual × Animation

Animation 属于 Visual 的动态表现层。

Animation 服务 Visual。

Visual 决定：

为什么动。

Animation 决定：

如何动。

任何动画不得违背 Visual Philosophy。

---

## Visual × Audio

Audio 提供：

听觉体验。

Visual 提供：

视觉体验。

二者共同营造 Journey 氛围。

不得互相干扰。

---

## Visual × QA

QA 验证：

Visual 是否符合正式规范。

QA 不定义：

视觉规则。

---

## Visual × Release

Release 负责交付。

Visual 负责：

正式视觉资源。

Release 不重新审核美术风格。

---

# 12. Documentation Maintenance

Visual Documentation 长期维护遵循以下原则。

## Principle One

Single Source of Truth。

每一条视觉规则。

只有唯一正式来源。

---

## Principle Two

No Duplication。

不得：

VISUAL_GUIDELINES

重复：

VISUAL_PHILOSOPHY。

不得：

BACKGROUND_GUIDELINES

重复：

VISUAL_STYLE_GUIDE。

---

## Principle Three

Architecture Before Assets。

先：

Documentation。

再：

视觉资源。

不得：

画完以后再制定规范。

---

## Principle Four

Visual Before Effects。

先：

阅读体验。

再：

动态效果。

任何动画。

不得影响：

故事。

学习。

阅读。

---

## Principle Five

Documentation Evolves。

Visual Documentation 可以持续完善。

但：

保持长期稳定。

避免：

频繁改名。

频繁调整结构。

# 14. Visual Documentation Version

Visual Documentation 拥有独立版本。

采用：

```text
Major.Minor.Patch
```

说明：

## Major

Visual Philosophy。

Visual Architecture。

整体视觉体系重大调整。

---

## Minor

新增：

正式 Documentation。

正式规范。

正式 Pipeline。

正式 Quality Gate。

---

## Patch

术语统一。

拼写。

引用。

排版。

说明优化。

不得改变正式视觉规则。

Visual Documentation Major Version 建议始终与 Documentation System Major Version 保持一致。

---

# 15. Permanent Rule

Phoenix Visual System 是 Phoenix 唯一正式视觉规范。

任何：

- Background
- Journey
- Illustration
- Banner
- Splash
- Loading
- Map
- Passport
- UI Illustration
- Animation
- AI Image

开始之前。

都必须：

1. 阅读 Visual README。
2. 根据任务进入对应 Documentation。
3. 遵循 Visual Philosophy。
4. 遵循 Visual Guidelines。
5. 遵循 Visual Style Guide。
6. 按 Decision Tree 判断。
7. 按 Pipeline 执行。
8. 通过 Image Quality Gate。
9. 完成 Visual Checklist。
10. 完成 Visual Review。

只有完整通过以上流程。

视觉资源才允许进入 Phoenix Official Visual Library。

任何绕过 Visual Documentation Navigation 的视觉开发流程，都不属于 Phoenix Official Visual Development Process。
