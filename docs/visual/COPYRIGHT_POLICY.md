# Phoenix Visual Copyright Policy

Documentation Status: Active  
Documentation Version: 1.0.0

本政策是 Phoenix 所有视觉资源的原创性、版权、商标、人格权、隐私、授权、来源追踪与商业使用强制入口，适用于 AI 原创图片、静态与动态背景、Journey 背景、首页、世界与城市地图、护照、生词、发现、挑战、留下印象、盖章、Banner、Loading、Splash、UI 插画、Icon、动画、视频、音视频中的视觉片段、摄影、纹理、字体相关视觉、第三方素材、程序化视觉及其他拟导入 Phoenix 的视觉资源。

本政策是内部产品治理规范，不构成法律意见。法律、司法辖区、平台条款、许可证或产品使用方式可能变化；实际使用前必须核验当时、当地及相应平台的有效规则。无法明确判断的复杂问题必须停止使用并升级至具备权限的人工法律审核，不得由 AI、开发者或产品人员推断授权成立。

## 1. 版权最高原则

1. Phoenix 只使用原创、可验证授权或经可靠证据确认允许商业使用的资源。
2. 可以在网络上找到不等于可以使用。
3. 由 AI 生成不自动代表不存在版权、商标、肖像、隐私或相似性风险。
4. 修改过不自动使资源成为原创或消除原权利。
5. 只使用一部分不自动构成合理使用；合理使用不得作为默认授权依据。
6. 用于教育不自动代表允许商业使用。
7. 授权、来源或权利状态不明时，禁止导入。
8. 版权风险不可由视觉评分、产品价值、教育价值、进度或开发成本补偿。
9. 任何角色均无权为了赶进度降低本政策标准。
10. 删除、断开或无法验证来源记录，等同于资源失去 Preview 与 Release 资格。

版权审查是零容忍发布门。视觉、Story、Learning、性能或页面 QA 的高分均不能覆盖权利失败。

## 3. 允许使用的资源

### 3.1 AI 原创资源

仅在以下条件全部满足时允许：生成平台当前有效条款覆盖预期商业用途；生成账户具有相应资格；平台、模型、版本、Prompt、输入、参数、原始输出与修改链可追踪；未以受保护角色、品牌、具体作品或具体艺术家的独特风格为复制目标；未上传无权使用的输入素材；相似性、商标、人物与版权风险审核通过；最终文件哈希与记录一致。

### 3.2 Phoenix 程序化原创资源

生成代码、输入数据、图形、纹理、字体及依赖必须由 Phoenix 自有或获得兼容授权。生成逻辑、版本和依赖须可追踪；开源代码许可证允许使用，不代表其示例图片、字体或素材自动可用。

### 3.3 Phoenix 人工原创资源

创作者必须以合同、雇佣条款或贡献协议明确授予 Phoenix 所需的商业使用、修改和分发权。作品不得包含未授权第三方元素；权利范围、地区、期限、媒介、署名及再利用规则必须清楚。

### 3.4 第三方授权资源

许可证必须明确商业使用、修改、分发、地区、期限、媒介、用户数量或流量等限制，并覆盖 Phoenix 的 Web、应用、宣传及计划使用方式。必须保存来源链接、购买凭证、许可证文本与版本，并满足署名、通知及展示要求。任何限制与产品模式冲突即不得使用。

### 3.5 公共领域资源

必须以可靠来源证明公共领域状态，并分别检查原作、特定扫描、摄影、数字修复、排版与数据库记录。原作进入公共领域不代表其现代复制版本自动自由使用。

### 3.6 开放许可证资源

必须核对具体许可证及版本、商业使用、修改、署名、相同方式共享、源文件或公开衍生作品义务、数据库权利与附加限制。若义务与 Phoenix 的闭源、商用或分发方式不兼容，须拒绝或升级法律审核。

## 4. 禁止来源

以下资源均为禁止来源：来源不明的网络图片；搜索结果直接下载内容；社交媒体截图；Pinterest、论坛或博客中的授权不明素材；影视、游戏、动画或漫画画面；出版物插图；商业摄影；未购买图库预览；带水印或移除水印素材；其他应用或网站的 UI 资产；未经授权地图；未经授权 Logo、品牌资产或角色；不明纹理、图标与字体；反向处理以掩盖来源的素材；无权提供者上传的内容；许可证兼容性无法确认的开源资源。

裁切、翻转、调色、模糊、拼接、重绘、AI 风格化、滤镜或局部替换均不会把禁止来源变为可用资源。发现禁止来源时应隔离文件、保留审计证据并将权利状态设为 `REJECTED`；不得继续优化、导入或公开展示。

## 5. AI 图片生成版权规则

### 5.1 生成前

必须核验生成平台当日有效条款、模型条款、账户商业资格、地区限制、输入素材权利、Prompt 的作品与品牌风险、具体艺术家风格风险、与现有作品高度相似风险，以及真实人物、未成年人、肖像和隐私风险。核验结果必须关联条款版本或存档证据。

### 5.2 生成记录

必须记录平台或模型、模型版本、生成日期、账户类型或授权依据、完整 Prompt、Negative Prompt、所有输入图片及其权利状态、Seed 或可用参数、原始输出、选择与修改过程、最终输出及文件哈希。平台不提供某参数时，应记录“平台未提供”及证据，而不是虚构数值。

### 5.3 生成后

必须检查受保护角色、品牌、Logo、看似真实的受保护作品、高度相似构图、艺术家签名、图库水印、错误版权标识、来源不明文字与符号，以及可能的记忆式复制。明显相似或复制风险必须返回 Prompt 与视觉方向阶段重新设计和生成，不得用局部修复、遮罩或裁切掩盖。

AI 生成记录还须按 [AI Image Generation Guide](./AI_IMAGE_GENERATION_GUIDE.md) 执行；视觉缺陷另由 [Image Quality Gate](./IMAGE_QUALITY_GATE.md) 管理。

## 6. 风格与模仿规则

宽泛、非专属且不指向特定创作者或作品的语言可以使用，例如电影感、东方美学、水墨氛围、儿童绘本感、历史文学感、柔和自然光、分层景深、克制插画风。这些描述仍须结合 Phoenix 自身的故事、构图、色彩与视觉语言形成原创方案。

禁止要求完全按照具体艺术家的独特风格、复制某部电影画面、制作某游戏同款、采用某动画公司的角色设计、重画著名插画或与某品牌广告完全一致。风格参考描述共同的媒介、时代、光线或构图属性；作品复制则保留可识别的独特表达、角色、布局、道具组合或品牌识别。若普通观察者可能将结果误认为特定作品、系列、艺术家或品牌的衍生物，应判为高风险，停止使用并重新设计；无法判断时升级人工法律审核。

## 7. 商标、品牌与 Logo

每项资源必须检查注册与未注册商标、品牌名称、Logo、产品包装、标志性外形、商业制服、品牌建筑标识，以及可能暗示赞助、认可或合作关系的组合。除非具有明确授权，或经法律审核确认属于必要且合法的事实性使用，不得把品牌或 Logo 作为装饰。

AI 意外生成疑似品牌标识时必须重新生成或在权利允许的原创源文件上彻底移除，并重新执行相似性、商标、Gate 与页面审核。不得创造使用户误以为 Phoenix 与某品牌、机构或权利人存在合作、赞助或官方关系的视觉内容。

## 8. 人物肖像、人格权与隐私

真实人物、公众人物、普通个人、未成年人、用户上传照片、员工或创作者照片、历史人物，以及虚构但高度类似真实人物的形象，均须单独审核。必须确认可识别性、肖像与商业使用授权、AI 编辑或变形权限、未成年人监护人同意、敏感场景、虚假代言、名誉风险、个人信息暴露、地区人格权规则及授权保存状态。

没有明确授权时，不得把可识别真实人物用于 Phoenix 商业视觉。公众人物身份不自动消除肖像、人格、隐私、商标或摄影作品权利。历史人物重建须检查肖像来源、摄影作品权利、博物馆或档案复制条件及相关地区规则。涉及未成年人、敏感信息、深度合成、虚假代言或权利冲突时必须进入人工法律审核。

## 9. 用户提供资源

用户上传不构成 Phoenix 对权利完整性的默认确认。接收时必须记录用户授权声明、使用范围、商业使用、AI 编辑、长期保存、撤回或到期条件，并检查其中第三方人物、品牌、作品、位置与敏感信息。授权声明必须能关联提供者、时间、版本与具体文件哈希。

声明不足、身份或授权链无法核验、高风险人物或受保护元素未清除时，资源只能分类为 `REFERENCE_ONLY_NOT_FOR_USE`，置于受限环境，不得进入正式资源库、公开分支、公开 PR Preview 或产品构建。

## 10. 文化、历史与传统内容

传统故事、神话、诗词和古典作品可能属于公共领域，但现代翻译、改编、当代插图、现代字体、博物馆摄影、数字修复、当代表演造型、特定出版物的排版与视觉表达可能仍受保护。Phoenix 可以依据经确认的公共领域原典进行原创设计，不得复制现代改编的独特表达。

记录必须包括原典来源、使用版本、公共领域判断依据、原创改编说明及文化审核结果。权利审核不能替代文化真实性审核，文化审核也不能证明版权许可；两者均通过才可发布。

## 11. 字体、图标、地图和界面资产

### 11.1 字体

必须分别检查 Web 使用、应用嵌入、商业使用、子集化、修改及再分发权限。免费下载安装不等于允许嵌入商业产品。字体文件、字形衍生视觉与许可证必须分别登记。

### 11.2 图标

必须检查图标库许可证、版本、署名、修改、品牌图标限制与应用打包权限。品牌图标不得因存在于通用图标库而被当作自由装饰。

### 11.3 地图

必须检查地图数据与瓦片许可证、署名、截图、缓存、离线、地理数据再分发、边界和地名准确性。数据许可与地图渲染样式许可应分别核验；未经授权的底图截图不得导入。

### 11.4 UI 资产

禁止复制其他产品的图标、页面布局、插图、动画、独特交互视觉或品牌化组件。通用交互模式的采用仍须以 Phoenix 的独立表达实现，并接受相似性审核。

## 12. 开源与第三方依赖

每个视觉相关依赖必须记录名称、版本、来源、许可证、商业使用状态、修改状态、署名与分发要求，以及所含字体、图标、纹理和示例资源。必须检查依赖树中许可证冲突、双重许可与附加条款。

尤其禁止：把代码许可误用于附带素材；把示例图片当成产品资源；升级依赖而不复核许可证变化；删除许可证文件；遗漏强制署名。依赖升级、来源迁移或许可证文本变化会使相关资源回到 `UNDER_REVIEW`，完成复核前不得发布新版本。

## 13. 权利与证据记录

每项视觉资源必须保存以下可追踪证据：Asset ID、文件名、文件路径、使用页面、Journey、资源类型、权利分类、创作者或生成平台、创建与生成日期、原始来源、来源链接或记录、许可证名称与版本、商业使用状态、修改权、分发权、署名要求、许可证副本位置、购买凭证、合同或授权文件、AI Prompt、输入素材及其权利状态、原始文件、优化文件、SHA-256、Git Blob SHA、审核人、审核日期、当前权利状态、有效期限和备注。

证据必须对应实际使用的文件版本。哈希改变即产生新版本并触发受影响权利复核；仅记录“原创”“已授权”或“看起来没问题”不构成证据。缺少证据时状态必须为 `MISSING_EVIDENCE`，不得进入 Preview 或 Release。

| `APPROVED_FOR_RELEASE` | 第 24 节全部条件通过 | 在批准范围、地区、期限和版本内发布 | 超范围或过期后继续使用 | 变更或到期即回审 |
| `EXPIRED` | 许可证、授权或有效期届满 | 下架、续期、替换 | 新 Preview、Release、继续分发 | 续期证据完成后回 `UNDER_REVIEW` |
| `TAKEDOWN_REQUIRED` | 投诉、禁令、条款变化或重大风险要求停用 | 保存证据、紧急移除与替换 | 继续公开或删除事件记录 | 仅经法律与权利复审后转换 |

`RIGHTS_UNCLEAR`、`RESTRICTED`、`REJECTED`、`EXPIRED` 和 `TAKEDOWN_REQUIRED` 均不得进入正式版。`APPROVED_FOR_PREVIEW` 不能推定 `APPROVED_FOR_RELEASE`。

## 15. 不可 Waive 阻断规则

以下 17 项为不可 Waive 阻断项：

| ID | 阻断条件 | 强制处理 |
|---|---|---|
| `RIGHTS-BLOCK-001` | 来源未知 | 隔离并拒绝导入 |
| `RIGHTS-BLOCK-002` | 许可证缺失 | 设为 `MISSING_EVIDENCE` |
| `RIGHTS-BLOCK-003` | 商业使用不明 | 停止并进入法律或权利审核 |
| `RIGHTS-BLOCK-004` | 明显复制现有作品 | 拒绝并重新设计 |
| `RIGHTS-BLOCK-005` | 未经授权角色 | 拒绝或取得明确授权 |
| `RIGHTS-BLOCK-006` | 未经授权品牌或 Logo | 拒绝或取得明确授权 |
| `RIGHTS-BLOCK-007` | 模仿具体艺术家的独特风格 | 停止并重新设计 Prompt 与视觉方向 |
| `RIGHTS-BLOCK-008` | 输入素材无使用权 | 拒绝输出并更换合法输入 |
| `RIGHTS-BLOCK-009` | 用户授权不足 | 限制为参考并补充授权 |
| `RIGHTS-BLOCK-010` | 肖像权或人格权不明 | 停止并进入人工法律审核 |
| `RIGHTS-BLOCK-011` | 未成年人授权不明 | 立即停止使用 |
| `RIGHTS-BLOCK-012` | 许可证与 Phoenix 分发方式冲突 | 拒绝或更换许可证兼容资源 |
| `RIGHTS-BLOCK-013` | 强制署名无法满足 | 禁止使用该资源 |
| `RIGHTS-BLOCK-014` | 许可证已经失效 | 停止使用、续期或替换 |
| `RIGHTS-BLOCK-015` | 收到权利人投诉 | 暂停使用并启动事件响应 |
| `RIGHTS-BLOCK-016` | 无法提供来源证据 | 设为 `MISSING_EVIDENCE` 或拒绝 |
| `RIGHTS-BLOCK-017` | 资源哈希与记录不一致 | 隔离实际文件并重新审核 |

这些条件不得由总分、Waiver、开发负责人、视觉负责人或产品负责人批准绕过，也不得标记为不适用。只有消除真实问题、补齐新证据并完成复审，才能解除阻断。

## 16. Review 与审批流程

权利流程依次为：资源提出 → 来源分类 → 权利证据收集 → AI 与相似性检查 → 许可证检查 → 商标与人物权利检查 → 文化内容检查 → 版权 Review → `IMAGE_QUALITY_GATE` → `VISUAL_CHECKLIST` → `VISUAL_REVIEW_PROMPT` → 页面级 QA → 正式批准。

| 审核方式 | 适用情况 | 权限边界 |
|---|---|---|
| 自动检查 | 必填字段、许可证允许列表匹配、哈希一致性、期限提醒、品牌或相似性初筛 | 只能发现问题和验证机械事实，不能作最终法律结论 |
| 人工权利审核 | 所有拟进入公开 Preview 或 Release 的资源 | 核对来源、授权范围、义务、输入输出与实际页面使用 |
| 人工法律审核 | 许可证含义不清、合理使用主张、跨地区冲突、商标事实性使用、肖像与隐私、未成年人、公共领域争议、投诉、复杂许可证兼容性 | 给出可记录的使用边界或拒绝决定 |
| 必须拒绝 | 禁止来源、明显复制、无权输入、不可修复授权冲突或无法取得证据 | 不得继续生产或公开 |
| 仅允许 Preview | 已达到 `APPROVED_FOR_PREVIEW` 但尚未满足正式版的非权利发布条件 | 权利本身仍须完全覆盖公开 Preview；不得含版权灰区 |

版权审核负责人确认权利记录；相关专业负责人确认商标、人物、隐私、文化、技术与页面使用事实；最终发布负责人只能在证据齐全后确认状态，不能替代法律判断。

## 17. Preview 与正式版区别

Preview 不是版权灰色地带。未经授权、来源不明或权利不清的资源禁止进入公开 Preview。公开 Preview 必须具有覆盖该公开展示、分发地区、平台和期限的完整权利。

封闭、受限且不可公开的原型如确需临时参考，资源必须标记 `REFERENCE_ONLY_NOT_FOR_USE`，与产品资源隔离，不提交公开分支，不进入公开 PR Preview，不打包进产品，不允许用户访问，并记录负责人和明确删除期限。正式发布前必须彻底删除或替换并验证构建中不存在残留引用。

## 18. 授权到期与变更

以下事件均触发重新审核：许可证到期或续期；订阅终止；授权平台或 AI 平台条款变化；资源使用范围变化；产品商业模式变化；新增发布地区或平台；资源再利用；重新授权；文件修改；依赖升级；权利人、创作者或供应商变化。

到期检查必须在有效期前产生提醒并指定负责人。永久许可也须核对订阅终止后对已下载资源的持续使用权。任何条件变化后，相关状态立即转为 `UNDER_REVIEW`；若已失效则转为 `EXPIRED`，复审通过前不得产生新的 Preview 或 Release。

## 19. 投诉、下架与替换流程

版权事件响应顺序为：收到投诉 → 登记事件与时间 → 保存投诉、当前文件及权利证据 → 临时停止使用 → 评估权利状态 → 必要时从 Preview 与正式版移除 → 创建合法替换资源 → 重新执行导入与页面 QA → 记录最终结论。

| 等级 | 条件 | 响应 |
|---|---|---|
| P0 紧急下架 | 有效禁令、明确侵权、未成年人或重大人格/隐私风险、权利人要求且风险可信 | 立即设为 `TAKEDOWN_REQUIRED`，停止分发并升级法律负责人 |
| P1 高风险暂停 | 可信投诉、授权范围可能冲突、重大商标或相似性问题 | 暂停公开使用，保全证据并优先审核 |
| P2 补充证据 | 权利可能成立但记录不完整或版本不一致 | 设为 `MISSING_EVIDENCE`，补证前不得新增发布 |
| P3 记录与优化 | 非阻断记录质量或署名展示改进 | 保留历史，在限定期限内修正并复核 |

不得删除投诉、原始文件、来源快照、通信或审核历史。公开下架完成后仍须检查缓存、CDN、离线包、缩略图和旧构建，并将替换关联到原 Asset ID 与事件记录。

## 20. 定期审计

每项资源在导入前和每次正式发布前必须审核。资源库至少按季度执行权利元数据、到期、哈希、未使用资源与许可证文件抽查；每个主要版本对实际打包资源执行全量清单比对。下列情况触发相关范围全量检查：许可证或平台条款变化、依赖升级、新地区或平台发布、商业模式改变、供应商变更、权利投诉、哈希异常、来源记录迁移或发现历史补证缺口。

抽查必须覆盖不同来源分类、高风险人物与商标、第三方授权、AI 模型、字体、地图和长时间未复审资源。任一抽查发现系统性缺陷、相同供应商问题、批量缺证或哈希不一致，立即扩大为同来源、同许可证、同 Journey 或全资源库检查。审计必须记录范围、样本、异常、处理人和关闭证据。

## 23. 固定 Rights Record 格式

Rights Record 是每个 Asset ID 的版本化结构化记录，供 AI、开发者和审核人员创建、更新、附证、审计与关联。字段定义如下：

| 字段组 | 必需字段 | 记录规则 |
|---|---|---|
| 标识 | Asset ID、文件名、文件路径、资源类型、版本 | Asset ID 稳定；文件变化产生新版本 |
| 使用 | 页面、Journey、地区、平台、Preview/Release 范围 | 必须与真实引用一致 |
| 来源 | 权利分类、创作者或生成平台、创建/生成日期、原始来源、来源链接或记录 | 混合资源逐项列出 |
| 许可 | 名称、版本、商业使用、修改、分发、署名、有效期限 | 使用明确枚举和原文证据引用 |
| 私密证据索引 | 许可证副本、购买凭证、合同、授权文件的证据 ID、受控位置与内容哈希 | 不在公开仓库保存敏感原文 |
| AI | 模型与版本、账户依据、Prompt、Negative Prompt、参数、输入素材及权利状态、原始输出 | 必须关联最终版本 |
| 文件 | 原始文件、优化文件、SHA-256、Git Blob SHA | 每次修改重新计算 |
| 审核 | 审核人、日期、当前权利状态、结论依据、有效期限、备注 | 不得删除旧审核 |
| 变更历史 | 时间、原状态、新状态、原因、操作者、证据 | 追加式记录 |
| 工程关联 | Commit、PR、资源引用、构建或 Release | 能追溯到实际发布 |
| 事件 | 投诉、下架、替换、事件等级、处置与关闭证据 | 关联原资源和替换资源 |

公开仓库只保存非敏感元数据、许可证名称、必要署名、状态、哈希和不可猜测的证据 ID。合同、购买凭证、身份证明、未成年人同意、私人通信、账户信息与含个人数据的原始授权文件存入权限受控的私密证据库。公开记录通过证据 ID 与内容哈希关联私密文件；访问遵循最小权限并记录审计日志。不得把私密证据路径、访问令牌或个人信息写入公开 Commit、PR、日志或 Review 输出。

状态、许可证、文件、Commit、PR、投诉或替换发生变化时必须追加历史事件；禁止覆盖旧值。记录本身不得复制无权存储的资源，只保存审计所需且合法持有的证据。

## 24. 最终发布判断

权利状态只有在以下条件全部满足时才可设为 `APPROVED_FOR_RELEASE`：来源明确；权利分类明确；商业使用允许；修改和分发权限符合实际需求；署名义务已满足；AI 输入与输出权利清楚；无明显复制风险；无未经授权品牌或角色；肖像、人格与隐私权已确认；许可证证据已保存；实际文件哈希一致；审核历史完整；无未解决投诉；权利未过期；全部不可 Waive 项通过。

最终判定规则：

- 任一条件缺证：`MISSING_EVIDENCE`，禁止 Preview 与 Release。
- 权利含义无法确定：`RIGHTS_UNCLEAR`，停止并升级人工法律审核。
- 任一不可 Waive 阻断存在：`BLOCKED` 或 `REJECTED`，不得以评分补偿。
- 仅公开 Preview 权利和全部 Preview Gate 通过：可为 `APPROVED_FOR_PREVIEW`，不得发布正式版。
- 全部权利、Visual Gate、Checklist、Review 和页面 QA 条件通过：方可为 `APPROVED_FOR_RELEASE`。

批准仅对记录中的文件哈希、用途、平台、地区、期限和版本有效。任何超范围使用均视为新任务，必须重新进入本政策审核。
